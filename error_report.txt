8. ROOT CAUSE ANALYSIS
--------------------------------------------------------------------------------
`insmod` reporting "No such device" on a Linux platform driver is the
userspace surface of probe() returning -ENODEV. In game.c, init is:

    return platform_driver_probe(&game_driver, game_probe);

`platform_driver_probe()` walks the platform-bus device list looking for
a node whose `compatible` matches one in `game_of_match[]`. If no such
node is found, it returns -ENODEV without ever calling our probe(), and
no misc device is registered -- which is exactly why /dev/game is
missing and `game_app`'s `open("/dev/game", ...)` fails with ENOENT.

The host-side device tree (final_project-hw/soc_system.dts:98) does
declare:

    game_peripheral_0: game@0x100000000 {
        compatible = "csee4840,game_peripheral-1.0";
        reg = <0x00000001 0x00000000 0x00000040>;
        ...
    };

so the *built* DT is correct. The mismatch is therefore between what
was built on the host and what the board is actually running.

Most likely cause (in priority order):
  (a) The freshly compiled soc_system.dtb was never copied to the
      board's FAT boot partition, so U-Boot is still loading an old DTB
      (e.g. the lab3 one) that has no game_peripheral node. This is the
      single most common explanation for "compiles fine, insmod says
      No such device".
  (b) The new soc_system.rbf was not copied either, so the FPGA still
      holds the previous bitstream. Even with a correct DTB the driver
      would still bind, but reads/writes would target unmapped fabric.
  (c) U-Boot's environment is not actually loading socfpga.dtb /
      soc_system.dtb at boot (e.g. fatload command points at a
      different filename).
  (d) The DTB on the SD card was overwritten by the distro and the
      game_peripheral_0 node was lost.

Confirmation steps to run on the board:
    ls /proc/device-tree/sopc@0/bridge@0xc0000000/
        -- look for a "game@..." entry
    cat /proc/device-tree/sopc@0/bridge@0xc0000000/game@*/compatible

    dmesg | tail -50
        -- after "insmod game.ko" should show "game: init" but no
           "game: probed" line, which confirms probe() never ran.
